# Soft Editorial Sound — v1 (Local-First)

Scope: new videos and specifically authorized audio revisions. No retroactive changes. Motion-first, VO after visual ACC, no external API or network in production. Read SOUND-DIRECTION-RULES.md and SFX-LOCAL-FIRST.md. This is an additive creative standard, not an assertion of natural recordings.

## Creative gate
- Real mouse, keys, physical connector, printer motor and paper: prefer locally reviewed actual recordings. Never label a synthetic tap or noise as real foley. If unavailable use a deliberate low-level graphic cue or silence; report the recording gap; do not call audio final. Do not use actual device sounds for graphical opacity/reflow if no physical action is shown.
- Subordinate navigation can be silent; choose only meaningful interactions. Contrast primary/secondary clicks, contextual menu, selection, confirmation and result. Don't add a beep to every menu or every transition. Use varied short attacks, subtle release and appropriate spectral balance; avoid piercing clicks, repetitive tone, and exaggerated impact. Avoid a fake Windows notification or fake send sound. Final hold remains silent unless approved otherwise.
- 21 new original synthesized assets in templates/sfx-library (editorial prefix); 20 used in Sharing Printer, all CC0-1.0. They are temporary designed SFX, not mouse/keyboard/printer recordings, not Real SFX/Earshot upstream output. Prefer actual recorded assets when acquired. Individual gain starts around -19 to -27 dB in this project only; do not treat these as universal mastering targets.
- At each meaningful beat mark role, impact/onset, tail, source license, choice/omit rationale. Trim/fade/EQ baked into WAV when used, keep gain and source editable. Do not stack old and new tracks. No scene-level audio inside frozen scenes.
- Render full + key segments in Remotion and listen A/B at equal perceived level on phone speakers/headphones, verify timing, softness, variation, intelligibility and lack of distracting artifacts. Check audio stream and peak; waveform metrics and static PASS are not perceptual QA. Never mark natural or final until user approves listening with VO.

## Text-adaptive track (opt-in only)
Keep manifest `soundImplementationContract: cue-track-v1`; optionally set `soundTrackVariant: text-adaptive-v1`. Copy `templates/sound-cue-track/SoundCueTrack.text-adaptive-v1.tsx` to `src/components/SoundCueTrack.tsx` and `SoundTyping.ts` alongside it. Both are canonical for this variant. Legacy template unchanged. Only use when visual text reveal actually follows a supported formula; verify it against source and test changed/empty Props.

Ready typing cue has one PCM16 WAV no longer than one frame, plus `typing: {prop,mode,originFrame,localStart,localEnd,...}`. Modes: rate (startSeconds, charsPerSecond; floor), offsets (increasing offsets from localStart; floor proportion of visible steps), round (round proportional progress). Start/end match the rule window, frame bounds inclusive. Cue impactFrame for typing marks window start, not necessarily first audible tap. One sound per frame of increased visible character count; if several characters appear in one frame use one sound. Empty or no visible increment = silent. Full/segment share one schedule; source and props only, not a claim of native editing of audio timeline. `textProps` at both entry callsites must map typing props to `p.<prop>` in first occurrence cue order. Maintain metadata when visual timing changes; do not edit approved visual to match sound. `qa:sound --strict` checks exact canonical track, valid prop/window/mode and WAV length. This is not a generic ASR alignment engine or proof of actual rendered sync.
